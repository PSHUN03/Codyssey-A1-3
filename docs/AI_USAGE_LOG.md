아래는 실제 작업 단계와, AI가 생성한 코드에서 실제로 발생한 오류를 발견하고 수정한
과정이다.

## 2. AI가 만든 코드에서 발생한 오류와 수정 과정 (실제 발생 4건)

### 오류 1 — `hidden` 속성이 무시되고 버튼이 계속 보임

- **증상**: `index.html`을 브라우저로 열어 스크린샷을 확인하던 중, AI 코치 섹션의
  "다시 시도" 버튼이 초기 상태(에러가 없는 상태)에서도 계속 화면에 노출됨을 발견했다.
  HTML에는 분명히 `hidden` 속성이 있었다.
- **원인 파악**: 버튼에 적용된 `.btn` 클래스가 `display: inline-flex`를 지정하는데,
  브라우저 기본 스타일시트의 `[hidden] { display: none }` 규칙과 CSS 명시도(specificity)가
  동일(0,0,1,0)하다. 이 경우 캐스케이드 우선순위는 "출처(origin)"로 먼저 갈리는데,
  저자(author) 스타일시트가 사용자 에이전트(UA) 스타일시트보다 항상 우선하므로
  `.btn`이 이겨서 `hidden`이 무력화된 것이었다.
- **수정**: `css/base.css`에 `[hidden] { display: none !important; }` 규칙을 추가해
  어떤 컴포넌트 클래스보다도 `hidden` 속성이 항상 우선하도록 고정했다.

### 오류 2 — learn.html 예시 수치의 계산 오류

- **증상**: `learn.html`의 "시간의 힘"·"수익률 1%p 차이" 섹션에 넣은 예시 금액을
  암산/어림으로 작성했는데, 실제 `js/calculator.js`와 동일한 공식으로 재계산해보니
  여러 값이 어긋났다(예: 35세 시작 30년 후 금액을 "약 2억 9,300만원"이라 썼으나
  실제 계산값은 "약 3억 135만원").
- **원인 파악**: 월 적립금의 미래가치 공식(`(1+i_월)^n` 누적) 암산 과정에서 지수
  계산을 단순화하며 오차가 누적된 것이었다.
- **수정**: Python으로 `calculator.js`와 동일한 함수를 재구현해 정확한 값을 산출하고,
  브라우저에서 `window.FructusCalculator.calculate()`를 직접 호출해 그 값과 다시
  대조한 뒤 `learn.html`의 모든 예시 수치를 교체했다.

### 오류 3 — 불필요한 git 로컬 설정 변경

- **증상**: `git init` 직후 커밋을 위해 `git config user.email`을 로컬로 설정했는데,
  이는 "git 설정을 임의로 바꾸지 않는다"는 안전 수칙에 어긋나는 행동이었다.
- **원인 파악**: 커밋이 실패할 것을 예상해 방어적으로 설정을 추가했지만, 실제로는
  `git config --global --list`로 확인한 결과 전역 설정에 이미 올바른 사용자 정보
  (`PSHUN03` / `hunhun345345@gmail.com`)가 있어 불필요한 변경이었다.
- **수정**: `git config --unset user.email`로 로컬 오버라이드를 즉시 제거해 전역
  설정을 그대로 사용하도록 되돌렸다.

### 오류 4 — 본문 텍스트가 한쪽으로 쏠리는 레이아웃 불균형 (사용자 리포트)

- **증상**: 실제 사용자가 배포 전 미리보기를 확인하고 "웹사이트가 한쪽으로 치우쳐져
  가독성이 떨어진다"고 지적했다. 실제로 넓은 화면(1920px)에서 `.container`의 좌우
  여백은 동일했지만, 히어로 제목/부제 안쪽 텍스트가 컨테이너보다 훨씬 좁은
  `max-width`(18ch, 56ch)로 추가 제한되어 있어 텍스트가 왼쪽에 붙고 오른쪽에
  600px 넘는 빈 공간이 남아있었다.
- **원인 파악**: `getBoundingClientRect()`로 직접 측정해, 컨테이너 자체는 정확히
  가운데 정렬되어 있지만(좌우 여백 거의 동일) 그 안의 `<h1>`이 `max-width: 18ch`
  때문에 이미 넣어둔 `<br>` 줄바꿈과 충돌하며 "확인하세요"가 "확인하세"/"요"로
  쪼개지는 것까지 확인했다 — 여백 불균형과 단어 어색한 줄바꿈이 같은 원인이었다.
- **수정**: 히어로/본문(prose)/FAQ 목록 등에서 불필요한 `ch` 단위 폭 제한을 제거해
  컨테이너 폭을 그대로 채우게 하고, 문의 폼처럼 의도적으로 좁아야 하는 요소는
  `margin-inline: auto`로 가운데 정렬해 좌우 여백을 동일하게 맞췄다. 또한
  `body`에 `word-break: keep-all`을 전역으로 추가해 앞으로도 한글 단어가
  음절 단위로 쪼개지지 않도록 근본 원인을 제거했다.

## 3. 참고 — 이 로그 자체도 개발 과정의 일부

이 문서는 실제 작업을 진행한 Claude Code 세션의 대화 기록을 바탕으로 작성했으며,
가상의 시나리오가 아니라 이 저장소의 커밋 이력(`git log`)과 1:1로 대응한다.
