# 복리 계산 공식 및 검증

`js/calculator.js`의 구현과 완전히 동일한 공식을 문서화한다.

## 1. 기호 정의

| 기호 | 의미 |
|---|---|
| `P` | 초기 금액 |
| `PMT` | 월 적립액 |
| `r` | 연 수익률(소수, 예: 5% → 0.05) |
| `m` | 연간 복리 횟수 (연복리=1, 월복리=12, 일복리=365) |
| `T` | 총 투자 기간(년 단위로 환산한 값) |
| `n` | 총 납입 개월 수 |

## 2. 기간 환산

- 년 입력: `T = n입력값`
- 월 입력: `T = n입력값 / 12`
- 일 입력: `T = n입력값 / 365`

계산기 내부에서는 `totalMonths = round(T × 12)`로 반올림한 "총 개월 수"를 기준으로
요약 카드와 연도별 표를 동시에 산출한다. 이는 일(day) 단위 입력처럼 `T`가 정수가
아닐 때도 표·그래프·요약 카드가 서로 어긋나지 않게 하기 위한 설계 결정이다
(예: 400일 → T = 1.0959년 → totalMonths = round(13.15) = 13개월).

## 3. 초기 금액의 미래가치

```
i = r / m
FV_P = P × (1 + i)^(m × T)
```

## 4. 월 적립액의 미래가치 (매월 말 납입, ordinary annuity)

선택한 복리 주기(m)와 무관하게, 월 적립금은 "월 실효이율"로 환산해 계산한다.

```
i_월 = (1 + r/m)^(m/12) − 1
n = T × 12  (실제 구현은 반올림한 totalMonths 사용)

FV_PMT = PMT × [ (1 + i_월)^n − 1 ] / i_월     (i_월 ≠ 0)
FV_PMT = PMT × n                                (i_월 = 0)
```

## 5. 최종 결과

```
FV(최종 평가금액)     = FV_P + FV_PMT
총 납입 원금           = P + PMT × n
총 이자                = FV − 총 납입 원금
총 수익률(%)           = 총 이자 / 총 납입 원금 × 100
```

화면에 출력하는 모든 금액은 원 단위로 반올림한다(`Math.round`).

## 6. 연도별 스케줄 (표/그래프)

`totalMonths`를 12로 나눈 몫만큼 "N년차" 행을 만들고, 나머지 개월(`totalMonths % 12`)이
있으면 마지막에 "N년 M개월"이라는 잔여 기간 행을 별도로 추가한다. 각 행은 해당
시점(개월 수)까지의 `FV_P`, `FV_PMT`를 다시 계산해 누적 원금·누적 이자·연말 평가금액을
구하고, "해당 연도 이자"는 직전 행과의 누적 이자 차이로 산출한다.

## 7. 계산 가정

- 월 적립액은 **매월 말**에 납입한다고 가정한다(월초 납입 아님).
- **세전(稅前)** 기준이며 이자소득세 등 세금을 반영하지 않는다.
- **물가 상승률(인플레이션)을 반영하지 않는다** — 표시된 금액은 명목 금액이다.
- 수수료·운용보수는 반영하지 않는다.
- 복리 주기가 선택한 값과 다르더라도, 월 적립금은 항상 "월 단위 실효이율"로 정확히
  환산해 계산한다(3항 공식).

## 8. 손계산 검증 케이스 (6건)

아래 값은 `js/calculator.js`와 동일한 수식을 Python으로 재구현해 계산한 결과이며,
실제 웹 화면(계산기)에 같은 입력을 넣었을 때와 원 단위까지 일치함을 확인했다.

| # | 입력 | 총 개월 | 최종 평가금액 | 총 납입 원금 | 총 이자 | 총 수익률 |
|---|---|---|---|---|---|---|
| 1 | P=10,000,000 / PMT=0 / 연5% / 연복리 / 10년 | 120 | 16,288,946원 | 10,000,000원 | 6,288,946원 | 62.89% |

| 3 | P=5,000,000 / PMT=300,000 / 연5% / 월복리 / 10년 | 120 | 54,819,731원 | 41,000,000원 | 13,819,731원 | 33.71% |

케이스 1은 적립금 없이 원금만 굴리는 경우, 케이스 2는 원금 없이 적립만 하는 경우,
케이스 5는 수익률 0%(이자 없음) 경계값, 케이스 6은 일(day) 단위 입력 환산을
각각 검증한다.

## 9. 부동소수점 처리

JavaScript의 `Math.pow`와 부동소수점 나눗셈으로 인한 오차는 최대 1원 미만 수준이며,
모든 화면 출력값은 `Math.round()`로 원 단위 반올림해 사용자에게는 오차가 보이지
않는다. 매우 큰 값(1조원 이상)이나 매우 긴 기간(100년)은 입력 단계에서 상한선으로
차단해 부동소수점 정밀도 문제를 예방한다(`LIMITS` 참고, `js/calculator.js`).
